# AST — Audio Separator & Transcriber

Локальное десктопное приложение под Windows для работы с музыкой: разделение трека
на вокал и минус, транскрипция в MIDI и анализ качества результата.

Всё считается **локально на вашей машине** — аудио никуда не отправляется.

## Что нового (обновление от 14.10.2026)

**Починен MP3 на входе и переделан выбор модели.**

1. **BS-разделение снова работает с MP3.** Было: загружаешь MP3 — падение
   `Failed to publish audio output … Supported file format but unsupported
   encoding`. Причина: библиотека `audio-separator` берёт формат записи из
   формата входа — читает тип кодека у MP3 (`MPEG_LAYER_III`) и пытается
   записать им же файл `.wav`; libsndfile такое сочетание отвергает. FLAC при
   этом «везло» случайно: у него тип `PCM_16`, годный для WAV. Теперь любой
   вход кроме WAV (MP3, FLAC, M4A, OGG) перекодируется в WAV во временный файл
   внутри `output/_bs_api_tmp/` и уже оттуда уходит в модель, а формат вывода
   жёстко задан как WAV в обоих местах, где его держит библиотека. Проверено
   живым прогоном на модели Viperx-1297: MP3, WAV и FLAC — все три работают.
   Подробности: `core/engines/bs_engine_api.py`, раздел «Формат входа» в шапке.
2. **Выбор модели теперь по задаче, а не по автору.** Открыв список, видно три
   понятных вопроса — «🎤 Убрать вокал (для караоке)», «🎸 Получить минус как в
   оригинале», «⚡ Быстро и просто» — и кнопку «Показать все модели (для профи)».
   В полном списке крупно понятное название («Без протечек вокала»), мелко —
   пояснение, а техническое имя, SDR, видеопамять и скорость убраны в подсказку
   при наведении. Подробности — в разделе «Выбор модели: три вопроса вместо
   26 названий».

Посмотреть глазами: `tools/ui_selector_shot.py` (снимок списка моделей) —
`--expanded` раскрывает полный список.

## Что нового (обновление от 11.10.2026)

Четыре улучшения, каждое проверено прогоном на реальных файлах.

1. **BS-Roformer считается Python-API, без отдельной программы.**
   Раньше на каждый трек запускался `audio-separator.exe` и заново грузил модель
   (~5–10 с). Теперь модель грузится один раз и остаётся в памяти приложения.
   Замер на 10-секундном клипе (модель Viperx-1297):

   | | 1-й трек | 2-й трек |
   |---|---|---|
   | было (`audio-separator.exe`) | 13.5 с | 13.4 с |
   | стало (Python-API) | 12.9 с | **7.7 с** |

   Результат при этом совпадает со старым трактом: расхождение 0.02 % от пика,
   корреляция 1.00000. Запасной путь никуда не делся — он включается флагом
   `use_api=False` у движка в `core/engines/__init__.py`.
   Гибрид пока ходит по старому пути (через `.exe`) — это следующий шаг.

2. **Метрики с эталоном: SDR / SIR / SAR.** Появился `tools/benchmark.py`:
   он прогоняет модели по трекам, где известен «правильный» ответ, и считает,
   насколько результат на него похож. Выбор модели перестал быть «на слух» —
   см. раздел [«Бенчмарк моделей»](#бенчмарк-моделей).

3. **Настройки правятся в окне.** Кнопка **«⚙ Настройки»** открывает диалог со
   всеми полями `config/settings.json`: подсказки, допустимые диапазоны, кнопка
   сброса. Руками править JSON больше не нужно (и не страшно).

4. **Волна показывает то, что играет.** Выбрали «Слушать: Вокал» — на график
   выходит вокал, «Минус» — минус, «Исходный трек» — исходник. Под волной
   подпись, какой именно файл нарисован.

Попутно исправлен баг CLI, который мешал проверять первое улучшение: подписи
движков содержат эмодзи («🏆 инстр»), а консоль Windows по умолчанию работает в
cp1251 — `cli.py` падал с `UnicodeEncodeError` в главном потоке, и настоящая
ошибка выглядела как загадочное «can't register atexit after shutdown».
Теперь CLI печатает в UTF-8 (`errors="replace"`), даже если кодировка системы
другая.

Проверки после всех правок: `153 passed` в `pytest tests/ -q`,
`tools/e2e_check.py` (Demucs + BS + гибрид + анализы — все OK),
`tools/benchmark.py` (4 модели × 5 треков, метрики посчитаны).

## Что умеет

- **Разделение на вокал и минус** тремя движками:
  - **Demucs** (`htdemucs`, `htdemucs_ft`) — быстро, ~3–5 минут на трек;
  - **BS-Roformer / Mel-Band Roformer** — 21 модель на выбор: убрать вокал для
    караоке, получить минус как в оригинале, выделить только вокал. Качество
    выше, но до 30 минут на трек;
  - **Гибрид** — вокал от Demucs, минус от BS-Roformer.
- **Постобработка стемов** — HPF, notch 2.5 кГц (по умолчанию **выключен**),
  LPF 19 кГц. Уровень выставляется **одним общим коэффициентом на пару**
  вокал+минус — чтобы стемы оставались комплементарными.
- **Транскрипция в MIDI** — вокал и минус через `torchcrepe`; отдельно
  «минус → фортепиано» через нейросеть MuScriptor.
- **Анализ аудио** — уровни, клиппинг, тишина, октавный спектр, стерео, грубая F0 + графики.
- **Супер-анализ пары «вокал + минус»** — метрики артефактов разделения
  (phase smearing, spectral tilt, transient loss, bleed score), карта подозрительных
  секунд и итоговый вердикт.
- **Анализ MIDI** — диапазон, октавы, топ нот, плотность, velocity, темп.

## Установка

```powershell
git clone https://github.com/zhorzhy6-eng/music-separator.git
cd music-separator
python -m venv .venv312
.\.venv312\Scripts\Activate.ps1
```

Дальше — зависимости, двумя шагами. Первый файл ставит всё, кроме torch:

```powershell
pip install -r requirements.txt
```

Второй — сам torch под CUDA 12.1. Он вынесен отдельно, потому что сборки `+cu121`
живут не на PyPI, а на индексе PyTorch; индекс уже прописан внутри файла:

```powershell
pip install -r requirements-gpu.txt
```

Сборка `torch 2.5.1+cu121` требует драйвер NVIDIA от 525.60.13. Если GPU нет,
поставьте обычный torch с PyPI — на CPU всё работает, но в разы медленнее:

```powershell
pip install torch torchaudio
```

Про `audio-separator`: приложение работает с ним двумя способами. По умолчанию
BS-модель считается **Python-API** этого пакета (модель грузится один раз за
сессию). Запасной путь — `.venv312\Scripts\audio-separator.exe`; он же нужен
гибриду. Если пакета нет вовсе, движки BS и «Гибрид» не работают.

## Токен Hugging Face

Часть моделей BS-Roformer лежит на Hugging Face в закрытых (gated) репозиториях —
для их скачивания нужен токен: https://huggingface.co/settings/tokens

Задайте его переменной окружения — код читать файлы с токеном не умеет:

```powershell
# только для текущей сессии
$env:HF_TOKEN = "hf_ваш_токен"

# либо постоянно, для текущего пользователя
[Environment]::SetEnvironmentVariable("HF_TOKEN", "hf_ваш_токен", "User")
```

`audio-separator` подхватит переменную сам. Модели Demucs, torchcrepe и MuScriptor
скачиваются без токена.

Картинки рисуются белыми и перекрашиваются в цвет темы при загрузке — поэтому
одна и та же иконка годится и для тёмной, и для светлой темы, и для кнопок
разных ролей. Если иконок нет (инструмент не запускали), кнопки показывают по
одному запасному символу — интерфейс остаётся читаемым.

### Четыре вкладки

| Вкладка | Что на ней | Когда кнопки активны |
|---|---|---|
| **Разделение** | карточка «Способ разделения» (26 моделей по группам), «Разделить на вокал и минус», прогресс-бар, «Отмена» | после загрузки файла |
| **Ноты** | «Вокал в ноты», «Минус в ноты», «Минус как пианино» | когда для текущего трека есть вокал и минус |
| **Качество** | «Проверить качество звука», «Проверить ноты», «Проверить качество разделения», «Открыть отчёты» | звук — после загрузки файла, ноты — после транскрипции |
| **Настройки** | все 11 полей `config/settings.json`, «Сохранить», «Вернуть как было» | всегда |

Правило одно: **кнопка включается тогда, когда для неё есть файл.** Не «вообще
есть», а именно для того трека, который сейчас загружен. Если разделили трек,
затем загрузили другой — кнопки вкладки «Ноты» погаснут, пока не разделите новый.

### Что видно, а что нет

- **Прогресс-бар и «Отмена» появляются только во время задачи.** Пустая полоса
  на экране не висит.
- **Волна без файла — заглушка 80 пикселей** с подсказкой, что делать. С файлом —
  120 пикселей и заливка с градиентом; оси и подписи убраны: «0.0–1.0» ничего
  не объясняли, а место занимали.
- **Пояснения живут в подсказках, а не на экране.** Наведите мышь на кнопку —
  всплывёт объяснение (например, почему «Минус в ноты» не подходит для аккордов).
- **Строка состояния говорит простыми словами:** «song.mp3 — 3:07, 44.1 кГц,
  стерео» → «Разделяем: обрабатываем голос… 75%» → «Готово: голос и музыка лежат
  в папке output». Технические названия стадий («Demucs: разделение») переведены.
- **Подсказка-шаг справа внизу** отвечает на вопрос «что дальше»: «Шаг 1: выберите
  файл», «Шаг 2: нажмите синюю кнопку…», «Готово: выберите „Вокал“ или „Минус“».

### Меню «⚙» в шапке

Одна кнопка вместо двух (раньше «🌗 Тема» и «⚙ Настройки» стояли рядом):

- **Светлая тема / Тёмная тема** — переключение сразу, без перезапуска;
- **Настройки…** — открывает вкладку «Настройки»;
- **Открыть папку output**, **Открыть отчёты** — те же две папки, что и раньше;

### Выбор модели: три вопроса вместо 26 названий

Раньше список моделей группировался **по автору** (Viperx, Duality, Gabox,
Becruily). Человеку, который не читает HuggingFace, это не говорит ничего:
«Viperx-1297» и «Gabox bleedless v2» — просто набор букв, и выбрать между ними
невозможно. Теперь выбор построен **по задаче**.

**Шаг 1 — три большие кнопки.** Открыв список, видно три вопроса:

| Кнопка | Что делает | Какую модель выберет |
|---|---|---|
| 🎤 **Убрать вокал (для караоке)** | Быстро, чисто, без протечек | Becruily karaoke |
| 🎸 **Получить минус как в оригинале** | Максимальное качество | Viperx-1297 |
| ⚡ **Быстро и просто** | Demucs, ~3 минуты | htdemucs_ft |

Нажали — модель выбрана, можно сразу нажимать «Разделить». Знать названия
моделей не нужно.

**Шаг 2 — «▸ Показать все модели (для профи)».** Раскрывает полный список,
разбитый по задачам:

| Группа | Что получится | Модели |
|---|---|---|
| 🎤 Убрать вокал (для караоке) | Голос уходит полностью, музыка остаётся | Becruily karaoke, Karaoke-Gabox / -V2, Karaoke-Aufr33, Gabox bleedless v1/v2/v3, Duality-V2 |
| 🎸 Минус как в оригинале | Музыка сохраняется максимально полно | Viperx-1297, Gabox fullness v1/v3, MelBand-Inst-V2, Big Beta 4, Big Beta 5e |
| 🎙 Только вокал | Нужен отдельно голос: акапелла, сэмплы, разбор партии | Viperx-1296, Becruily vocals, Unwa FT, Unwa FT2 bleedless |
| ⚡ Быстро и просто | Считает за минуты, работает почти на любой видеокарте | htdemucs, htdemucs_ft |
| 🎹 Гибриды: Demucs + BS | Голос от Demucs, музыка от BS-модели: дольше всех, ровнее | Demucs_ft + Viperx-1297 / Duality-V2 / Becruily karaoke |
| 🔧 Прочее | Редкие и старые модели: для сравнения | Becruily inst, Duality-V1, BS-Roformer-SW |

В каждой строке списка:

* **крупно** — понятное название: «Без протечек вокала», «Максимум
  инструментала», «Лучший вокал»;
* **мелко серым** — пояснение в одну строку и, в скобках, техническое имя;
* **✅** — так помечена выбранная сейчас модель;
* **«рекомендуется»** — модели, с которых стоит начинать: Duality-V2,
  Becruily karaoke, Gabox bleedless v2, Viperx-1297, Viperx-1296, htdemucs_ft
  и гибрид Demucs_ft + Duality-V2.

**Наведите мышь на строку** — появится подсказка: техническое имя (Viperx-1297,
Duality-V2…), полное описание, SDR, нужная видеопамять и скорость.

Что где лежит в коде:

* `core/engines/__init__.py` — поля `group` (задача), `plain_name` (понятное
  название), `plain_desc` (пояснение), `technical_name` (для подсказки),
  `recommended`, плюс `Preset` и `PRESETS` — сами кнопки-пресеты и правило,
  какую модель они выбирают;
* `ui/engine_selector.py` — только отрисовка: группы, строки, подсказки.

Добавить модель по-прежнему = добавить одну строку в `ENGINES`. Если у новой
модели не заполнены `plain_name`/`plain_desc`, она не пропадёт из списка —
покажется под своим техническим именем.

## Переезд проекта ⚠️

**Виртуальное окружение `.venv312` нельзя переносить на другой путь.**

`.exe`-файлы в `.venv312\Scripts\` — это обёртки-ярлыки, внутри которых зашит путь
к python'у на момент установки. Если папку проекта переименовать, переместить на
другой диск или скопировать на другой компьютер, все 47 обёрток будут показывать
в никуда и молча падать.

Что при этом ломается: **гибрид** и запасной путь BS через `audio-separator.exe`
(они запускают `.exe`). Что продолжает работать: **BS-Roformer** (считается
Python-API прямо в приложении, `.exe` не нужен), Demucs, транскрипция в MIDI и
анализы — они используют библиотеки Python напрямую.

Симптом: «🔀 Разделить» с гибридом сразу падает с `audio-separator упал с кодом 1`.

Что делать: **не переносить `.venv312`, а пересоздать его** на новом месте.
Пошаговая инструкция с тремя вариантами решения — в [docs/FIX_VENV.md](docs/FIX_VENV.md).

Начиная с версии от 11.10.2026 приложение проверяет обёртку перед запуском и вместо
безмолвного «упал с кодом 1» пишет, какой именно путь внутри неё сломан.

## Настройки

Всё, что можно менять без правки кода, лежит в `config/settings.json` — но править
его руками больше не нужно: в окне есть вкладка **«⚙ Настройки»** (и пункт
«⚙ Настройки…» в меню шапки). Там те же поля, с подсказками и проверкой значений;
при сохранении файл настроек переписывается, и новые значения начинают действовать
**сразу**, без перезапуска (следующая задача берёт их из обновлённого конфига).

| Ключ | По умолчанию | Что делает |
|---|---|---|
| `default_engine` | `BS-Roformer: Duality-V2 ✅ баланс` | какой движок выбран при запуске |
| `demucs_device` | `cuda` | устройство для Demucs: `cuda`, `cuda:0`, `cpu` |
| `demucs_shifts` | `1` | сколько проходов делает Demucs (больше = качественнее и медленнее) |
| `demucs_overlap` | `0.25` | перекрытие окон Demucs |
| `notch_enabled` | `false` | резать ли 2.5 кГц в минусе (см. ниже — по умолчанию выключено) |
| `target_peak` | `0.891` | целевой пик выходных файлов (≈ −1 dBFS) |
| `output_sample_rate` | `44100` | частота выходных WAV |
| `keep_temp_dirs` | `false` | `true` — не удалять промежуточные папки (для отладки) |
| `bs_use_fp16` | `false` | считать BS-модель в половинной точности (меньше видеопамяти) |
| `bs_batch_size` | `0` | размер батча BS-модели; `0` — как в конфиге модели (обычно 1) |
| `bs_keep_model_loaded` | `true` | держать BS-модель в памяти между треками (экономит ~5–10 с на трек) |

Значения вне разумных границ не ломают тракт: приложение напишет предупреждение
в лог и возьмёт значение по умолчанию. Диалог настроек такие значения просто не
даст сохранить — покажет, что именно не так.

Полезно знать:

- **`bs_keep_model_loaded` и видеопамять.** Закэшированная BS-модель занимает в
  видеопамяти ~600–700 МБ (замер на Viperx-1297). Перед запуском Demucs или гибрида
  приложение само освобождает этот кэш — иначе две модели на 6 ГБ не помещаются.
  Если видеопамяти мало в принципе, включите `bs_use_fp16`.
- **`demucs_device=cpu`** — рабочий вариант без видеокарты, но в разы медленнее.
- **`output_sample_rate` влияет только на новые прогоны.** Уже разделённые файлы
  остаются на прежней частоте — меняйте настройку до разделения.


## Модели

Модели BS-Roformer / Mel-Band Roformer (`.ckpt`, от 600 МБ до 1.7 ГБ) качаются
с Hugging Face **в `models/` внутри проекта** — приложение передаёт CLI

(`/tmp/audio-separator-models`, на Windows — относительно текущего диска),

- каталог можно переносить вместе с проектом — повторно ничего не качается;

- модели Demucs и MuScriptor качает сам PyTorch в `%USERPROFILE%\.cache\torch`

## Архитектура: ресторан

Приложение разделено на четыре роли. Смысл разделения один: изменение в одной
роли не должно ломать три остальные.

| Роль | Кто это в коде | Что делает |
|------|----------------|------------|
| **Официант** | `ui/app_window.py`, `ui/viewmodels.py` | принимает заказ (кнопки, файлы), показывает ход дела. Про кухню не знает |
| **Менеджер** | `core/worker.py` | решает, что и когда готовить: две очереди, отмена, закрытие смены |
| **Повар** | `core/engines/*`, `core/*_analyzer.py` | готовит: разделяет, транскрибирует, считает метрики. Про зал не знает |
| **Меню** | `core/engines/__init__.py` (реестр `ENGINES`) | описывает блюда: какие движки есть, что каждый умеет |

### Как это работает на практике

1. **Меню — один список.** Все модели живут в `core/engines/__init__.py`.
   Выпадающий список в окне строится из него же. Добавить модель = добавить одну
   строку в `ENGINES`; раньше список приходилось править в трёх файлах, и они
   успели разъехаться. Там же, у каждой BS-модели, стоит флаг `use_api`: `True` —
   считать Python-API пакета (по умолчанию), `False` — запускать
   `audio-separator.exe` (запасной путь).
2. **Один договор для всех движков.** `core/engines/base.py::Separator` описывает
   ровно одно умение: `separate(файл, куда, прогресс) → StemSet`. Движок выбирает
   фабрика `make_separator(spec)` — воркеру всё равно, Demucs это, BS-Roformer
   или гибрид.
3. **Заказ и отчёт — типизированные.** Разделение возвращает `StemSet`
   (не «голый» словарь), супер-анализ показывает окну `VerdictView`
   (`core/reports.py`). Схема отчёта — внутреннее дело анализатора: поменять её
   можно, не трогая интерфейс.
4. **Очередь бережёт видеокарту.** GPU-задачи (разделение, транскрипция, пиано)
   идут строго по одной: на 6 ГБ две модели одновременно не помещаются.
   Анализы (без GPU) идут по два.
5. **Работу можно отменить.** Кнопка «⏹ Отмена» останавливает задачу, а
   `audio-separator.exe` гасится вместе с дочерними процессами. Закрытие окна
   делает то же самое — в диспетчере задач ничего не остаётся.
6. **Кнопки рисуются из состояния.** `UiState` + `_refresh_actions()` — одна
   точка правды: пока идёт работа, кнопки запуска выключены, а после ошибки они
   включаются не «слепо», а по факту (есть ли для текущего трека нужный файл).

Правило для правок: ядро (`core/`) не знает про виджеты, край (`ui/`) общается с
ним через `core/worker.py` и его события.

## Бенчмарк моделей

Выбор модели перестал быть «на слух»: `tools/benchmark.py` прогоняет модели по
трекам с известными стемами и считает SDR / SIR / SAR.

Что означают метрики:

- **SDR** — насколько результат похож на эталон;
- **SIR** — насколько подавлен «чужой» источник (вокал в минусе и наоборот);
- **SAR** — сколько артефактов добавила модель.

Везде больше = лучше, единица измерения — децибел. Считать метрики умеет
`mir_eval` из `requirements-dev.txt`; без него бенчмарк тоже работает, но считает
упрощённые метрики и честно пишет об этом в отчёте.

```powershell
# 1. эталонные треки: сгенерировать синтетические (свои можно положить рядом)
.\.venv312\Scripts\python.exe tools\make_benchmark_data.py

# 2. прогон моделей
.\.venv312\Scripts\python.exe tools\benchmark.py
.\.venv312\Scripts\python.exe tools\benchmark.py --engines bs:duality-v2 demucs:htdemucs_ft
.\.venv312\Scripts\python.exe tools\benchmark.py --list      # какие движки есть и где нет модели
```

Формат эталонов — папка на трек: `mix.wav`, `vocals.wav`, `instrumental.wav`
(44100 Гц; другая частота пересчитывается автоматически). Свои треки дают честные
числа, синтетика — только сравнимые между моделями.

Результаты: `logs/benchmark/summary.md` (таблица), `benchmark_<модель>.json`
(подробности по каждому треку) и `logs/benchmark/separated/` (стемы — можно послушать).

## Параметры DSP

Все параметры обработки — константы в начале модулей либо в `config/settings.json`.
Общие для всего проекта вещи (целевой пик, нормализация пары, фильтры) живут
в `core/dsp.py` и больше не дублируются по модулям.

### Нормализация: один коэффициент на пару

`core/dsp.py::normalize_pair` нормирует вокал и минус **одним общим коэффициентом**
до целевого пика из настроек (`target_peak`, по умолчанию `0.891` ≈ −1.0 dBFS).

Почему так: если нормировать стемы по отдельности, их взаимный уровень ломается —
сумма перестаёт соответствовать оригиналу, а вся аналитика уровней начинает
измерять нашу же обработку, а не трек.

Дополнительно встроенная нормализация BS-тракта отключена: у CLI это
`--normalization 1.0`, у Python-API — `normalization_threshold=1.0`. По умолчанию
и CLI, и API сами подтягивают каждый стем к пику 0.9, что тоже разрушает
комплементарность пары.

В **гибриде** вокал приходит из Demucs, а минус — из BS-Roformer, поэтому обе
ветки нормировку отключают (`normalize_pair_output=False`), а уровень финальной
пары выставляется один раз — `core/dsp.py::normalize_pair_files`. Иначе каждая
ветка тянула бы уровень на себя, и баланс вокала и минуса уезжал.

### Notch 2.5 кГц: по умолчанию выключен

Notch управляется ключом `notch_enabled` в `config/settings.json` (по умолчанию
`false`). Провал в районе 2–3 кГц — это гитары, струнные и атака малого, то есть
самая разборчивая зона, поэтому по умолчанию минус не фильтруется вообще.

Если notch всё-таки нужен, он строится как честный peaking-EQ (RBJ biquad),
и `INSTR_NOTCH_GAIN_DB_REAL` — это **реальная глубина в дБ** на центральной частоте:

| Значение | Что получится |
|---|---|
| `-1.5` | провал ровно −1.5 dB (значение по умолчанию для BS-тракта) |
| `-3.0` | провал ровно −3.0 dB (значение по умолчанию для Demucs-тракта) |
| `-6.0` | провал ровно −6.0 dB |

Раньше здесь была самодельная смесь `filtered*gain + sig*(1-gain)`, у которой
заявленные −3.0 dB давали фактический провал −10.7 dB, а −1.5 dB — целых −16 dB.
Проверено замером: новый фильтр даёт на 2500 Гц ровно −3.00 dB.

### Критичные

1. **Порядок clip → normalize в сохранении файлов.**
   Было: `np.clip` до нормализации — срезало верхушки транзиентов (грязь на бочке
   и щелчках), а последующая нормализация это маскировала, и в логе пик выглядел
   «ровно −0.3 dBFS». Стало: сначала общий коэффициент нормализации, `clip` —
   только страховка. Если страховка всё-таки сработала, в лог пишется предупреждение
   с числом обрезанных сэмплов.
2. **Двойная независимая нормализация вокала и минуса.**
   Было: `audio-separator.exe` подтягивал каждый стем к 0.9, потом AST подтягивал
   каждый стем ещё раз отдельно к своему пику. Стало: `--normalization 1.0`
   в CLI плюс один общий коэффициент на пару (`core/dsp.normalize_pair`).
   Проверено: отношение «минус/вокал» сохраняется точно (2.000000 → 2.000000).
3. **Notch 2.5 кГц — дырка в музыке.**
   Было: самодельная смесь давала фактическую глубину −10.7 dB (Demucs) и −16 dB (BS)
   вместо заявленных −3.0 и −1.5 dB. Стало: notch выключен по умолчанию
   (`INSTR_NOTCH_ENABLED = False`), а при включении это честный peaking-EQ
   (RBJ biquad), где параметр — реальная глубина. Проверено замером АЧХ:
   заявлено −3.0 dB → фактически −3.00 dB.

### Высокие

4. **`_transient_loss` считал разницу по частоте, а не по времени.**
   Было: `np.diff(spec)` внутри одного кадра — это спектральный наклон.
   Стало: `spec - prev_spec` (spectral flux между кадрами). На реальном минусе
   метрика перестала быть вырожденной: flux активных кадров 95.6 против 88.9 тихих,
   тогда как старая формула давала разницу в обратную сторону (−7.9%).
5. **Гибрид не проверял выравнивание вокала и минуса.**
   Добавлена `_assert_aligned()`: сверяет sample rate и длины с допуском 1 мс
   перед копированием финальных файлов. Рассинхрон теперь ловится ошибкой,
   а не тихо портит результат.
6. **`_poll_events` глотал все ошибки через `except: pass`.**

   сбой на одном событии логируется и не останавливает остальные.

## Ограничения

- Отмена долгих задач работает, но не мгновенно: Demucs останавливается между
  шагами, BS-Roformer через Python-API — на ближайшем батче инференса (обычно
  меньше секунды), BS через `.exe` — убийством дерева процессов.
- Лимита параллельных задач нет — несколько прогонов на GPU съедят видеопамять.
  GPU-задачи при этом идут строго по одной (см. `core/worker.py`).
- Драг-энд-дроп в интерфейсе заявлен, но не подключён.
- `tkinterdnd2` установлен, но в коде не применяется.
- Нота остаётся монофонической моделью: `torchcrepe` ведёт одну F0, поэтому
  аккорды и полифония в MIDI не разложатся (для минуса есть отдельный путь
  «Минус → Пианино» через MuScriptor).
- Общий коэффициент нормализации пары означает, что громкость стемов зависит
  от самого громкого из двух: если минус заметно громче вокала, вокал получится
  тише, чем при раздельной нормализации. Так задумано (комплементарность важнее),
  но на слух это надо проверять.
- **Гибрид теперь тоже считает BS-ветку через Python-API** (как и одиночный
  BS-Roformer), `.exe` остаётся запасным путём (`use_api=False`). Раньше гибрид
  всегда поднимал `audio-separator.exe` и после переезда `.venv312` ломался;
  теперь это лечится тем же, чем и одиночный BS-движок.
- **Закэшированная BS-модель занимает видеопамять** (~600–700 МБ). Перед Demucs и
  гибридом приложение кэш освобождает само; если видеопамяти мало, отключите
  `bs_keep_model_loaded` или включите `bs_use_fp16` в «⚙ Настройки».
- **Прогресс BS-API идёт от батчей инференса**, а не от времени: на медленной
  видеокарте он «замирает» на границах шагов — это нормально, а не зависание.

### Про транскрипцию (по итогам QA-прогона 11.10.2026)

- **«Минус → MIDI» — только для одноголосного материала.** На полноценном миксе
  torchcrepe отдаёт единицы нот: в QA-прогоне вышло 58 нот на 4 минуты. Теперь
  приложение пишет об этом предупреждение в лог и показывает подсказку в окне.
  Для полифонии используйте «🎹 Минус → Пианино».
- **Фортепианная партия — это переложение, а не ноты «как в оригинале».** Низкие
  ноты поднимаются на октаву вверх, одинаковые ноты в один момент сливаются.
  Число разных высот ограничено самим материалом: если гитара играет 21 разную
  ноту, больше 21 в партии не появится.
- **Супер-анализ сообщает о покрытии.** Если вокал сжат по динамике и «активных»
  кадров мало, вердикт теперь прямо предупреждает: «Покрытие низкое — метрики
  основаны на малой выборке». Это честнее, чем уверенный вывод по 0.2 секунды.
- **`output_sample_rate` влияет только на новые прогоны.** Уже разделённые файлы
  остаются на прежней частоте — меняйте настройку до разделения.

## Известные ограничения

### BS-разделение не работает после переезда проекта

Подробности и три варианта лечения — в [docs/FIX_VENV.md](docs/FIX_VENV.md).
Коротко: `.venv312` нельзя переносить на другой путь, его надо пересоздавать.
На этой машине временно действует обходной путь — junction `E:\Python\AST` →
`E:\Programmy\AST`; после пересоздания venv его стоит удалить (`rmdir "E:\Python\AST"`).

Замечание после прогона 11.10.2026: самому приложению эта ссылка **больше не
нужна** — BS-разделение идёт через Python-API (`core/engines/bs_engine_api.py`),
а не через `audio-separator.exe`. Ссылка нужна только тем путям, которые всё
ещё поднимают `.exe`: запасной BS-движок (`use_api=False`) и запуск
`audio-separator.exe` вручную.

### CUDA-рассинхрон: torch cu121 против onnxruntime-gpu

`torch` ставится сборкой `+cu121` (CUDA 12.1), а `onnxruntime-gpu` — обычным
пакетом с PyPI, и он собирается под ту CUDA, которая была актуальна на момент
релиза. Если мажорные версии разъедутся, ONNX-провайдер **молча уйдёт на CPU**:
ошибок приложение не покажет, просто BS-Roformer станет в разы медленнее.

Как это выглядит в логе:

```
Failed to load cudart64_13.dll
...
[audio-separator] Using CPU
```

Что делать:

1. Посмотреть, какие провайдеры реально доступны:

   ```powershell
   .\.venv312\Scripts\python.exe -c "import onnxruntime as ort; print(ort.get_available_providers())"
   ```

   Если в списке нет `CUDAExecutionProvider` — провайдер не собрался под вашу CUDA.

2. Сверить версии:

   ```powershell
   .\.venv312\Scripts\python.exe -c "import torch; print(torch.__version__, torch.version.cuda)"
   .\.venv312\Scripts\python.exe -m pip show onnxruntime-gpu
   ```

3. Поставить `onnxruntime-gpu` под ту же CUDA, что и torch (для CUDA 12 это
   ветка 1.18–1.20), либо поставить CUDA-рантайм нужной мажорной версии.
4. Эталон работающей комбинации — в `requirements.lock.txt`
   (`torch 2.5.1+cu121` + `onnxruntime-gpu 1.30.0`).

Замечание: `torch 2.5.1+cu121` и `onnxruntime-gpu 1.30.0` стоят в одном окружении
одновременно, но это не гарантирует, что ONNX действительно использует GPU —
проверяйте список провайдеров, а не факт установки пакета.

### Прочие ограничения

- **Demucs отдаёт стемы чуть короче исходника.** На прогоне 11.10.2026 трек
  187.41 с превратился в пару по 186.044 с: модель считает целыми сегментами и
  хвост короче сегмента отбрасывает. Оба стема совпадают между собой, парная
  нормализация и супер-анализ работают, но последняя секунда трека в ноты не
  попадёт. Это поведение самой модели, а не обработки AST.
- **Фильтры минуса (HPF 25 Гц + LPF 19 кГц) дают перерегулирование.** В прогоне
  11.10.2026 пик минуса после фильтров поднимался до 1.19 (то есть +1.5 dB выше
  нуля), и срабатывала страховка: «Перегруз фильтров 1.1861 — масштабирую до
  0.99». В финальных файлах клиппинга нет (0 полношкальных сэмплов), но минус
  из-за этой страховки становится тише вокала на ~1.5 dB. Лечится подбором
  порядка/частот фильтров — это правка DSP, а не интерфейса.
- **Сохранение настроек переписывает запись движка.** После «Сохранить» в
  `config/settings.json` вместо подписи («BS-Roformer: Duality-V2 ✅ баланс»)
  лежит её id («bs:melband_roformer_instvox_duality_v2.ckpt») и дописываются
  поля `bs_*` со значениями по умолчанию. Поведение не меняется:
  `resolve_engine_id` понимает обе формы.
- **Супер-анализ молчит, когда измерять нечего.** Если в треке нет вокала
  (на разделение подали готовый минус), вердикт прямо говорит об этом, а VPI,
  наклон спектра и «подозрительные секунды» не показываются: раньше в этом
  случае выходило «отпечаток голоса 139.8 дБ» и «минус темнеет −65 %» —
  числа, посчитанные от тишины.
- Пик пары нормализуется до 0.891 (≈ −1.0 dBFS) — если раньше стемы были громче,
  после обновления они станут тише примерно на 0.7 dB. Это ожидаемо.
- `notch` выключен по умолчанию: если он был нужен для подавления голосового
  отпечатка, его придётся включить вручную (`INSTR_NOTCH_ENABLED = True`)
  и подобрать `INSTR_NOTCH_GAIN_DB_REAL` по слуху.
- `torchcrepe` тянет модель с интернета при первом запуске; без сети транскрипция
  не заработает.
- Медианное сглаживание F0 (окно 5 кадров ≈ 50 мс) слегка сглаживает быстрые
  форшлаги и глиссандо — это осознанный компромисс против рваных нот.
- `config/settings.json` перезаписывается приложением только если файла нет;
  правки в нём подхватываются при следующем запуске.
