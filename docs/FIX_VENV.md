# Если BS-Roformer и гибрид перестали работать (мёртвые .exe-обёртки venv)

## Как это выглядит

- Нажимаешь «🔀 Разделить» с движком `BS-Roformer` или `Hybrid` — ничего не происходит,
  через секунду выскакивает ошибка:
  `audio-separator упал с кодом 1` (и больше ни строчки объяснений).
- Demucs, транскрипция в MIDI и анализы при этом работают как обычно.
- В `logs\ast.log` строка `Запуск audio-separator` есть, а следом сразу `Задача упала`,
  между ними меньше секунды.

## Почему так

Представь, что `.venv312` — это кухня, а файлы `.exe` в папке `.venv312\Scripts\` —
это **адресные таблички** на дверях: «повар живёт по адресу `E:\Python\AST\.venv312\Scripts\python.exe`».
Таблички печатаются один раз, при установке, и внутри них зашит адрес на тот момент.

Проект переехал с `E:\Python\AST` на `E:\Programmy\AST`. Кухня (`.venv312`) переехала
вместе с ним, а **адреса на табличках остались старые**. Теперь 47 табличек показывают
в никуда, и Windows не может запустить эти программы — они молча падают с кодом 1.

Пострадали **все 47 обёрток**: `audio-separator.exe`, `pip.exe`, `demucs.exe`,
`muscriptor.exe` и остальные. Живые только `python.exe` и `pythonw.exe` — это настоящие
программы, а не таблички, поэтому Demucs, torchcrepe и MuScriptor работают: приложение
вызывает их как библиотеки Python, а не через `.exe`.

Проверить, что дело именно в этом, можно так (PowerShell в папке проекта):

```powershell
# покажет путь, зашитый внутрь обёртки
$b = [IO.File]::ReadAllBytes(".\.venv312\Scripts\audio-separator.exe")
([Text.Encoding]::ASCII.GetString($b) -split "`0" | Select-String '#!').Line
```

Если увидишь `#!E:\Python\AST\...` (или другой путь, которого больше нет) — это оно.

---

## Вариант A — правильный: пересоздать окружение

Занимает 20–40 минут (зависимости тяжёлые, качается torch и onnxruntime).
Нужен интернет. Старое окружение удаляется полностью.

```powershell
cd E:\Programmy\AST

# 1. Убрать старое окружение
Remove-Item -Recurse -Force .venv312

# 2. Создать новое (тот же python 3.12)
python -m venv .venv312

# 3. Активировать
.\.venv312\Scripts\Activate.ps1

# 4. Поставить зависимости
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
python -m pip install -r requirements-gpu.txt
```

Проверка (обе команды должны напечатать справку, а не ошибку):

```powershell
.\.venv312\Scripts\audio-separator.exe --help
.\.venv312\Scripts\pip.exe --version
```

Потом запустить приложение: `run.bat`. Первый прогон BS-движка скачает модели
(см. README, раздел «Модели») — это нормально.

> Важно: `requirements.txt` и `requirements-gpu.txt` должны лежать в корне проекта.
> Если pip чего-то не нашёл — смотри `requirements.lock.txt`: там записаны версии,
> на которых проект точно работал.

## Вариант B — быстрый: починить обёртки одного инструмента

Если ждать 30 минут не хочется, а нужен только audio-separator (именно он отвечает
за BS-Roformer и гибрид):

```powershell
cd E:\Programmy\AST
.\.venv312\Scripts\python.exe -m pip install --force-reinstall --no-deps audio-separator
.\.venv312\Scripts\audio-separator.exe --help
```

Минус варианта: остальные 45 обёрток (`pip.exe`, `demucs.exe`, `muscriptor.exe`…)
останутся мёртвыми. Приложению они не нужны — оно вызывает эти библиотеки напрямую,
но из командной строки ими пользоваться не получится.

---

## Вариант C — временный: ссылка на старый путь

Одна команда возвращает к жизни **все 47 обёрток сразу**: создаётся «зеркало» старого
адреса, которое ведёт на новый.

```powershell
# Создать (нужны права обычного пользователя, администратор не требуется)
New-Item -ItemType Directory -Force -Path "E:\Python" | Out-Null
cmd /c mklink /J "E:\Python\AST" "E:\Programmy\AST"

# Проверить
.\.venv312\Scripts\audio-separator.exe --help
```

Удалить зеркало, когда оно перестанет быть нужным:

```powershell
rmdir "E:\Python\AST"     # именно rmdir, НЕ Remove-Item -Recurse
```

Что важно знать про вариант C:
- это **заплатка**, а не лечение: она держится на том, что папка `E:\Python\AST`
  существует. Если проект переедет ещё раз — всё сломается снова;
- зеркало создаёт только ссылку, места на диске оно не занимает;
- **на этой машине вариант C уже применён** (11.10.2026), чтобы можно было прогнать
  BS-разделение. Пока ссылка есть — BS работает. После пересоздания venv
  (вариант A) ссылку нужно удалить командой `rmdir` выше.

## Чтобы это не повторилось

**Виртуальное окружение `.venv312` нельзя переносить на другой путь.**
Если проект нужно переместить — переноси всё, кроме `.venv312`, а окружение создай
заново на новом месте (вариант A). То же самое, если проект копируют на другой
компьютер или переименовывают папку верхнего уровня.

## Как понять, что всё вылечено

```powershell
cd E:\Programmy\AST

# 1. Обёртка жива
.\.venv312\Scripts\audio-separator.exe --help

# 2. Ни одной обёртки со старым путём внутри
Get-ChildItem .\.venv312\Scripts\*.exe | ForEach-Object {
    $t = [Text.Encoding]::ASCII.GetString([IO.File]::ReadAllBytes($_.FullName))
    if ($t -match '#!E:\\Python\\AST') { "ЕЩЁ СЛОМАНА: $($_.Name)" }
}
# Если команда ничего не напечатала — все обёртки в порядке.
```

Затем в приложении: «🔀 Разделить» с движком `BS-Roformer: Duality-V2 ✅ баланс`.
Должно отработать и написать в лог `BS-Roformer разделение завершено`.

Если BS всё ещё падает — смотри последние 20 строк вывода CLI прямо в тексте ошибки:
начиная с версии от 11.10.2026 приложение показывает их в диалоге (раньше показывало
только «упал с кодом 1»).
